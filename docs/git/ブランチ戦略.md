## 1. 基本方針

このアプリは**1人開発**を前提としており、シンプルな運用を優先する。

- PR・コードレビュー・CI は導入しない
- タグ管理は行わない
- コミット粒度は問わない（作業の区切りで随時コミット）
- ブランチはフェーズ単位で管理する

---

## 2. ブランチ構成

```
main
└── release/1.3
└── release/1.4
└── release/2.0
    ...
```

| ブランチ | 役割 |
|---------|------|
| `main` | フェーズ完了版を管理するブランチ。各 `release/*` のマージ先 |
| `release/{version}` | フェーズの開発作業ブランチ。1フェーズにつき1ブランチ |

---

## 3. 命名規則

| 対象 | 形式 | 例 |
|------|------|----|
| リリースブランチ | `release/{major}.{minor}` | `release/1.3`、`release/2.0` |

バージョン番号は `docs/` 以下の各フェーズドキュメントのバージョンと対応させる。

---

## 4. 開発フロー

### フェーズ開始時

```zsh
# main から新しいリリースブランチを切る
git checkout main
git checkout -b release/1.3
```

### フェーズ中（開発作業）

```zsh
# 作業の区切りで随時コミット（粒度は問わない）
git add -A
git commit -m "feat: ..."
```

### フェーズ完了時

```zsh
# main にマージして完了
git checkout main
git merge release/1.3

# マージ後、リリースブランチは削除してよい
git branch -d release/1.3
```

---

## 5. コミットメッセージ規則

Conventional Commits に準拠する。

| プレフィックス | 用途 |
|--------------|------|
| `feat:` | 新機能の追加 |
| `fix:` | バグ修正 |
| `refactor:` | リファクタリング（機能変更なし） |
| `docs:` | ドキュメントのみの変更 |
| `chore:` | ビルド設定・依存パッケージ更新など |
| `style:` | フォーマット・コードスタイルのみの変更 |

```
# 例
feat: Phase 1.3 保管フロー実装
fix: Google Sign-In iOS フリーズ修正
docs: Phase 1.3 要件定義書・詳細設計書 作成
refactor: BoxStatus tampered 表示名を「異常検知」に変更
```
