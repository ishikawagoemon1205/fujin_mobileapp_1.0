## 1. このフェーズの目的

### 何を作るか

封神を「**1人で使うアプリ**」から「**信頼できる人と一緒に使えるアプリ**」に拡張する。

Phase 1.1 までは「自分が封印して、自分が確認・開封する」という1人完結モデルだった。
Phase 1.2 では **「友達」と「グループ」という概念を導入し、封印物の共同管理と通知を実現する**。

### なぜ今やるか

封神の核心的な価値は「**この梱包物は、誰にも開けられていない**」ことを証明することにある。

しかし、封印物を**自分1人で管理している限り、その証明価値は限定的**である。なぜなら、物体が常に自分の手元にある状況では、そもそも他人に開けられるリスクが発生しないからだ。封神の本来の証明力が試されるのは、「**物体を他人に預ける・他人が関与する**」場面においてである。他人が介在するからこそ、「本当に開けられていないか」という疑義が生まれ、それを証明するデジタル記録の価値が生きてくる。

Phase 1.0・1.1 では、機能の動作確認と認証基盤の整備を優先した。Phase 1.2 では、**複数人が関与する現実のユースケースに対応することで、封神の証明価値を実環境で検証する**ことを目的とする。

- 家族が「どこに何が封印されているか」をお互いに確認できる
- 誰かに頼んで封印してもらったとき、完了を通知で受け取れる
- 会社・チームで封印物を共同管理し、開封の証跡を関係者全員が確認できる

これらを実現することで、封神は「個人の証明ツール」から「**信頼グループの証明基盤**」に進化し、封印・証明という価値の有効性を実際のユーザーとともに検証できる段階に入る。

## 2. 用語定義

このフェーズで導入する概念を定義する。LINE の用語を参考にし、一般ユーザーが直感的に理解できる言葉を使う。

| 用語 | 意味 |
|------|------|
| **友達** | 相互に同意して繋がったユーザー同士の関係。友達にのみグループ招待が可能 |
| **グループ** | 複数の友達が集まって封印物を共同管理する単位。最大5人 |
| **オーナー** | グループを作成したユーザー。メンバーの追加・削除・グループ解散ができる |
| **メンバー** | グループに参加しているユーザー。封印・確認・開封が可能 |
| **通知** | 封印・開封などのイベントをアプリ内およびプッシュ通知で受け取る機能 |

## 3. 実装する機能

### 3-1. 友達機能

#### 友達になる方法

友達になるには**必ず双方の同意**が必要である。一方的に繋がることはできない。

**方法1：QRコードで追加（対面）**

1. 自分のユーザーQRコードを相手に見せる
2. 相手がQRをスキャンする
3. 相手のアプリに「友達申請を送りますか？」の確認が表示される
4. 送ると自分に「友達申請が来ました」という通知が届く
5. 自分が承認 → 友達成立

**方法2：招待リンクで追加（遠隔）**

1. 自分のアプリで招待リンクを生成する（期限：72時間）
2. LINEやメールなど任意の手段でリンクを相手に送る
3. 相手がリンクを開くとアプリが起動し、友達申請の確認画面が表示される
4. 相手が申請を送ると自分に通知が届く
5. 自分が承認 → 友達成立

#### 【将来構想】特許技術を活用したユーザーQRシールとの連携

クライアント企業が保有する封印シール特許（複数の2次元バーコードによる改ざん検知）の技術思想を、ユーザー認証にも応用することを将来的に検討する。

具体的には、Webアプリ側でユーザーごとの「横長ユーザーQRシール」を発行し、1枚のシールに「識別QR」と「認証QR」の2つを並べて印刷する。対面での友達追加時に両方のQRをスキャンして初めて申請が完成する仕組みにより、画像キャプチャによる不正申請を防ぎ、「物理的に同席している」ことを担保できる。

> Phase 1.2 ではWebアプリ側との連携コストが高いため、アプリ内の1QRスキャンで申請できる基本形を実装する。将来フェーズでWebアプリとの連携が整った段階で、特許技術を活用した物理シール連携に移行する。

#### 友達の管理

- 友達一覧を閲覧できる
- 友達を削除できる（削除すると相手の友達一覧からも消える）
- 友達を削除しても、共有済みの封印データは残る

### 3-2. グループ機能

#### グループ作成

1. 友達一覧からグループに招待するメンバーを選ぶ（自分を含め最大5人）
2. グループ名を設定する
3. グループが作成され、招待されたメンバーに通知が届く
4. メンバーが承認するとグループに参加する（承認制）

> **制約**：グループメンバーに追加できるのは「友達」のみ。友達でない人は追加不可。

#### グループの管理

| 操作 | できる人 |
|------|---------|
| メンバーを追加する | オーナーのみ |
| メンバーを削除する | オーナーのみ |
| グループ名を変更する | オーナーのみ |
| グループを解散する | オーナーのみ |
| グループから退出する | メンバー（オーナーは不可。解散のみ）|

#### グループの上限

| 制約 | 上限 |
|------|------|
| グループの最大人数 | 5人（オーナー含む） |
| 1ユーザーが属せるグループ数 | 制限なし |

---

### 3-3. 封印時のグループ共有

封印の手順に「共有設定（任意）」を追加する。

**変更後の封印フロー**

1. 写真撮影・メモ・保管場所を入力する（既存と同じ）
2. QRシールをスキャンする（**UX改善：連続スキャン対応**）
3. **【新規】共有設定を選ぶ（任意）**
   - 「共有しない」（デフォルト）→ 自分だけに見える従来の動作
   - 「グループを選ぶ」→ 自分が属するグループ一覧から選択
4. 「封印する」ボタンで確定

**共有されたときの動作**

- グループメンバー全員の封印一覧に、この箱が表示される
- グループメンバー全員に「〇〇さんが封印しました」という通知が届く

**開封の制限**

グループ共有された箱は、**そのグループのメンバーのみが開封できる**。グループ外のユーザーは、たとえ箱のQRコードを読み取れたとしても開封操作を実行できない。

> **注意**：一度共有したグループは封印後に変更できない。変更が必要な場合は箱を削除して再封印する。

### 3-4. 通知機能

#### 通知の種類

| イベント | 通知先 | 通知内容 |
|---------|--------|---------|
| 自分の箱がグループ共有された（封印完了） | グループメンバー全員 | 「〇〇さんが [箱の保管場所] を封印しました」 |
| グループ共有された箱が開封された | グループメンバー全員 | 「〇〇さんが [箱の保管場所] を開封しました」 |
| グループ共有された箱が破損検知された | グループメンバー全員 | 「[箱の保管場所] で破損が検知されました」 |
| 友達申請が届いた | 申請を受け取った本人 | 「〇〇さんから友達申請が届いています」 |
| 友達申請が承認された | 申請を送った本人 | 「〇〇さんと友達になりました」 |
| グループに招待された | 招待された本人 | 「〇〇さんが [グループ名] に招待しました」 |

#### 通知の受け取り方

- **プッシュ通知**：アプリがバックグラウンドでも受け取れる（Firebase Cloud Messaging）
- **アプリ内通知画面**：過去の通知が一覧で確認できる。既読・未読の管理あり

### 3-5. 封印QRスキャンのUX改善（連続スキャン対応）

#### 背景

Phase 1.0・1.1 では、封印用のQRスキャンは「1回のカメラ起動で1枚だけ読み取り、読み取り後に自動的にカメラ画面を閉じる」仕様だった。複数のQRシールを貼る場合、毎回カメラ画面を開き直す必要があり、操作が煩雑だった。

#### 改善内容

1回のカメラセッションで**複数のQRコードを連続してスキャン**できるようにする。

**改善後の操作フロー**

1. 封印画面で「QRをスキャン」をタップ → カメラ画面が開く
2. 1枚目のQRをスキャンすると、読み取り成功のフィードバックが表示され、**カメラは閉じずにそのまま次のQRを待つ**
3. 読み取り済みのFace ID（F1, F2, ...）がカメラ画面の下部にリアルタイムで一覧表示される
4. 全てのQRを読み終えたら「**スキャン完了**」ボタンをタップ → 封印画面に戻る
5. 「✕」ボタンでカメラを閉じた場合も、**それまでに読み取ったQRは全て保持される**（破棄されない）

**完了ボタンの条件**

- 1枚以上のQRを読み取っていれば「スキャン完了」ボタンが有効になる
- 0枚の状態ではボタンは無効（グレーアウト）

**エラー時の動作**

- 異なる箱のQR、重複するFace ID、無効なQRコードを読み取った場合はエラーメッセージを一時的に表示し、カメラは閉じずにスキャンを継続する

## 4. 追加・変更する画面

### 4-1. 新規追加

| 画面名 | 概要 |
|--------|------|
| **友達一覧画面** | 友達の一覧表示・QRコードでの追加・招待リンク生成 |
| **友達申請画面** | 届いた友達申請の承認・拒否 |
| **マイQRコード画面** | 自分のユーザーQRコードを表示する |
| **グループ一覧画面** | 参加中のグループ一覧 |
| **グループ作成画面** | グループ名設定・メンバー選択 |
| **グループ詳細画面** | メンバー一覧・グループ設定・グループ内の封印一覧 |
| **通知画面** | アプリ内通知の一覧（既読・未読） |

### 4-2. 既存画面の変更

| 画面名 | 変更内容 |
|--------|---------|
| **ホーム画面** | 通知バッジの追加・プロフィール名と写真の表示・友達/グループへのナビゲーション追加 |
| **封印画面** | 共有グループ選択ステップの追加 |
| **封印QRスキャン画面** | 連続スキャン対応（1回のカメラセッションで複数QR読み取り・完了ボタン・スキャン済みFace IDリスト表示） |
| **封印一覧画面** | 個人の封印物とグループの封印物を1つの画面で表示。フィルター（すべて／個人／グループ別）で切り替えられる |
| **箱詳細画面** | 共有情報（共有グループ名）の表示を追加 |

### 4-3. 封印一覧画面の設計方針

年齢層が高いユーザーも使いやすいよう、**個人とグループの封印物を1つの一覧画面に統合する**。別画面に分けず、以下のシンプルなフィルターで切り替える。

```
封印一覧
  ┌──────────────────────────────┐
  │ [すべて] [個人] [家族] [仕事] │  ← タブまたはフィルターチップ
  └──────────────────────────────┘
  箱カード（グループ共有の場合はグループ名バッジを表示）
  箱カード
  ...
```

- デフォルトは「すべて」表示
- グループ共有の箱にはグループ名のバッジを表示し、個人の箱と視覚的に区別できる
- フィルターは「すべて」「個人」と、参加中の各グループ名で構成される（グループ数に応じて自動で増減）

| 既存機能 | 変更内容 |
|---------|---------|
| 封印一覧 | 個人・グループ共有の封印物を統合表示。フィルター機能を追加 |
| 箱詳細 | 共有情報（共有グループ名）を表示 |
| 封印フロー | 最後にグループ選択ステップが追加される |
| 封印QRスキャン | 連続スキャン対応。1回のカメラセッションで複数QR読み取り可能に改善 |
| 開封フロー | グループ共有箱はグループメンバーのみ開封可能。グループ外からの開封操作をブロックする |

## 6. Phase 1.2 でやらないこと（意図的な除外）

| 機能 | 除外理由 |
|------|----------|
| 匿名配達・第三者へのワンタイム共有 | 変数が多く複雑になるため。将来フェーズで対応 |
| メール通知 | MVPとして不要。将来的に対応予定 |
| viewer ロール（閲覧専用） | ニーズ未検証。将来的に対応 |
| グループ人数の上限拡大 | 将来的にプラン制などで対応する可能性がある |
| 既存封印物への後付けグループ共有 | 封印後の共有先変更は証明の観点から不整合を起こす可能性があるため除外 |
| 箱の転送（オーナー変更） | Phase 2 以降の検討事項 |
| メールアドレス・ユーザーIDによるユーザー検索 | プライバシー問題につき除外。QRと招待リンクのみで繋がる設計を維持 |

## 7. Phase 1.2 完了の定義

以下の全条件を満たした時点で Phase 1.2 完了とする。

1. QRコードでの友達申請・承認が動作する
2. 招待リンクでの友達申請・承認が動作する
3. 友達削除が動作する
4. グループ作成・招待・承認・退出・解散が動作する
5. グループ人数が5人を超える場合は追加できない
6. 封印時にグループを選択して共有できる
7. 共有された箱がグループメンバーの封印一覧に表示される
8. 個人・グループの封印物が1つの封印一覧画面でフィルター切り替えできる
9. グループ共有された箱の開封は、そのグループのメンバーのみ実行できる
10. 封印・開封・破損・友達申請・グループ招待の各イベントで通知が届く
11. アプリ内通知画面で過去の通知が確認できる（既読・未読管理あり）
12. プッシュ通知がバックグラウンドで受信できる
13. ホーム画面にプロフィール名と写真が表示される
14. 封印QRスキャン画面で1回のカメラセッションから複数QRを連続スキャンできる
