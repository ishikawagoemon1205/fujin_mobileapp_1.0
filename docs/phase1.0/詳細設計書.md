## 2. ディレクトリ構成

### 設計思想・ディレクトリ構成の意図

#### 目指している最終形：Clean Architecture

このアプリが最終的に目指すアーキテクチャは **Clean Architecture** である。

Clean Architecture では、各機能を以下の3層に分離する。

```
features/{feature}/
  ├── presentation/   # UIと状態管理（Widget、ViewModel）
  ├── domain/         # ビジネスロジック（UseCase、Repository インターフェース）
  └── data/           # 外部データアクセス（Firestore、Storage の実装）
```

この分離によって得られる主なメリットは次の通りである。

- **テスタビリティ**: ビジネスロジック（domain）をFirebaseに依存せず単体テストできる
- **保守性**: Firebase を別のバックエンドに差し替えても domain/presentation に影響しない
- **責務の明確化**: 「UIが何を表示するか」と「データをどこから取るか」が混在しない

#### Phase 1.0 の現状：不完全な移行途中

**Phase 1.0 はこの最終形への過渡期として位置づけており、構造は不完全な状態にある。**

MVPとして最速でリリースするため、`domain/` と `data/` の分離は行わず、Firebase へのアクセスを `shared/services/` に一本化した。各 feature の画面（`presentation/`）がサービスを直接呼び出す、いわゆる「Fat Presentation Layer」の状態である。

`seal/` にのみ空の `data/` と `domain/` ディレクトリが存在するのは、途中まで Clean Architecture への移行を試みた痕跡であり、設計上の意図ではない（技術的負債として認識済み）。

#### なぜ Feature-first の骨格は作ったか

完全な Clean Architecture への移行は Phase 2 以降に持ち越したが、**機能をまたいだ依存が将来的にスパゲッティにならないよう**、feature 単位の分割だけは Phase 1.0 の段階で確立した。

この骨格があることで、Phase 2 以降に各 feature へ `domain/` と `data/` を追加する際に、他の feature を壊さずに段階的に移行できる。

#### 現状の構造における各ディレクトリの役割

| ディレクトリ | Phase 1.0 での実態 | 最終形での役割 |
|------------|------------------|--------------|
| `core/` | ルーター・テーマ・定数・QRユーティリティ（全機能共通） | 変わらず横断的基盤 |
| `features/{name}/presentation/` | UI ＋ Firebase 直接呼び出しが混在 | UIと状態管理のみ |
| `features/{name}/domain/` | 未実装（空） | UseCaseとRepositoryインターフェース |
| `features/{name}/data/` | 未実装（空） | FirestoreやStorageの具体的な実装 |
| `shared/services/` | Firestoreへの全アクセスを集約（暫定措置） | data層へ分散後は廃止予定 |
| `shared/models/` | 全機能で使うデータモデル | 変わらず共有モデル |
| `shared/widgets/` | 複数 feature で再利用するUI部品 | 変わらず共有Widget |

## 3. データモデル

### 3-1. Box（箱）

```dart
class Box {
  final String boxId;           // 8文字 Base62（QRのbox-id）
  final DateTime createdAt;     // 封印日時
  final DateTime updatedAt;     // 最終更新日時
  final BoxStatus status;       // sealed | opened | tampered
  final String storageLocation; // 保管場所（テキスト）
  final int qrFaceCount;        // 登録QR面数
  final DateTime? openedAt;     // 開封日時（未開封ならnull）
  final DateTime lastViewedAt;  // 最終確認日時
  final Map<String, QRFace> faces;  // Face ID → QR面情報
  final List<BoxPhoto> photos;      // 写真リスト
  final String memo;                // メモ
  final List<BoxHistory> history;   // 操作履歴
}
```

### 3-2. BoxStatus（ステータス）

```dart
enum BoxStatus {
  sealed('sealed', '未開封'),   // 封印中
  opened('opened', '開封済み'), // 正常開封
  tampered('tampered', '破損'), // QR検証失敗
}
```

### 3-3. QRFace（QR面情報）

```dart
class QRFace {
  final String faceId;      // F1, F2, F3...
  final String qrCode;      // fujin://boxId/faceId/checksum
  final DateTime scannedAt;  // スキャン日時
  final String checksum;     // 4文字 CRC-16
}
```

### 3-4. BoxPhoto（写真情報）

```dart
class BoxPhoto {
  final String url;           // ダウンロードURL
  final String storagePath;   // Storage内パス
  final DateTime uploadedAt;  // アップロード日時
}
```

### 3-5. BoxHistory（操作履歴）

```dart
class BoxHistory {
  final DateTime timestamp;  // 操作日時
  final String action;       // sealed | viewed | opened | tampered
  final String details;      // 操作の詳細説明
}
```

## 5. 画面遷移（ルーティング）

### ルート定義

| パス | 画面 | パラメータ |
|------|------|-----------|
| `/` | HomePage | なし |
| `/seal` | SealPage | なし |
| `/verify` | VerifyPage | なし |
| `/box-list` | BoxListPage | なし |
| `/box/:boxId` | BoxDetailPage | `boxId`: 箱のID |
| `/unseal/:boxId` | UnsealPage | `boxId`: 箱のID |

### 遷移フロー

```
HomePage (/)
  ├── 「新しく封印する」 → SealPage (/seal)
  │     └── QRスキャン → SealQRScanPage（Navigator.push、Beamer外）
  │           └── スキャン完了 → pop → SealPage に戻る
  │     └── 封印完了 → HomePage (/) へ beamToNamed
  │
  ├── 「中身を確認する」 → VerifyPage (/verify)
  │     └── QRスキャン → 箱情報表示（同一画面内で切替）
  │     └── 「開封する」 → UnsealPage (/unseal/:boxId) へ beamToNamed
  │
  └── 「封印一覧」 → BoxListPage (/box-list)
        └── 箱タップ → BoxDetailPage (/box/:boxId) へ beamToNamed
              └── 「開封する」 → UnsealPage (/unseal/:boxId) へ beamToNamed
```

### 遷移方法の使い分け

| 方法 | 使用箇所 | 理由 |
|------|----------|------|
| `context.beamToNamed()` | 大部分の画面遷移 | Beamer のルーティングスタック管理に従う |
| `Navigator.push()` | SealPage → SealQRScanPage | Beamer管理外のモーダル的な遷移。スキャン完了後にpopで戻る |
| `context.beamBack()` | 戻る操作 | Beamer のバックスタックを使った戻り |

## 6. 処理フロー詳細

### 6-1. 封印フロー（SealPage）

```
[入力画面表示]
    │
    ├─ 写真追加: ImagePicker → File → selectedPhotos リスト
    ├─ メモ入力: TextField → memoController
    ├─ 保管場所入力: TextField → storageLocationController
    │
    ├─ 「QRをスキャン」タップ
    │     └─ Navigator.push → SealQRScanPage
    │           ├─ MobileScanner でQR検出
    │           ├─ QRCodeUtils.validateQRCode() でフォーマット検証
    │           ├─ QRCodeUtils.parseQRCode() で boxId, faceId, checksum 抽出
    │           ├─ box-id 一致チェック（2枚目以降）
    │           ├─ face-id 重複チェック
    │           ├─ 成功 → onQRScanned コールバック → 1秒後に自動pop
    │           └─ エラー → エラーメッセージ表示（スキャン継続）
    │     └─ pop で SealPage に戻る
    │
    ├─ scannedQRCodes に追加（faceId → qrCode の Map）
    │
    └─ 「封印する」タップ
          ├─ バリデーション（QRあり、保管場所あり）
          ├─ 重複チェック: Firestore に同じ box-id が存在しないか確認
          ├─ 写真アップロード: StorageService.uploadBoxPhoto() × N枚
          │     └─ compressImage() → putData() → getDownloadURL()
          ├─ Box オブジェクト生成
          ├─ FirestoreService.createBox() でFirestoreに保存
          └─ 完了 → SnackBar + beamToNamed('/')
```

### 6-2. 確認フロー（VerifyPage）

```
[QRスキャン画面表示] (isScanning: true)
    │
    ├─ QRScanPage（共通Widget）で QR検出
    ├─ QRCodeUtils.extractBoxId() で box-id 抽出
    │
    ├─ isScanning → false, isLoading → true
    │
    ├─ FirestoreService.getBox(boxId)
    ├─ FirestoreService.updateLastViewedAt(boxId)
    │
    └─ [箱情報表示] (isLoading: false)
          ├─ ステータスカード（色分け表示）
          ├─ 基本情報（保管場所、封印日時）
          ├─ 写真ギャラリー
          ├─ メモ
          └─ 「開封する」ボタン（sealed の場合のみ）
                └─ beamToNamed('/unseal/$boxId')
```

### 6-3. 開封フロー（UnsealPage）

```
[箱情報取得] (isLoading: true)
    │
    ├─ FirestoreService.getBox(boxId)
    ├─ ステータスチェック（sealed 以外なら戻る）
    │
    └─ [開封確認画面] (isLoading: false)
          ├─ 開封手順の説明表示
          │
          └─ 「QRスキャンを開始」タップ (isScanning: true)
                │
                ├─ QRScanPage（連続モード）でQR検出
                ├─ box-id 一致チェック
                ├─ 登録済み face-id チェック
                ├─ 重複スキャン除外
                ├─ scannedFaces に追加
                ├─ SnackBar で進捗表示（N/M枚スキャン完了）
                │
                └─ 全面スキャン完了
                      ├─ FirestoreService.updateBoxStatus(boxId, opened)
                      ├─ FirestoreService.addHistory(boxId, ...)
                      └─ 完了ダイアログ → beamToNamed('/')
```

## 7. QRコード処理（QRCodeUtils）

### 7-1. 生成

```
generateBoxId()
  → Random.secure() で 8文字 Base62 ランダム文字列

generateFaceId(int faceNumber)
  → 1-9: "F1"〜"F9"
  → 10以降: "F" + Base62文字

generateChecksum(String boxId, String faceId)
  → CRC-16-IBM (poly reversed 0xA001, init 0x0000)
  → 入力: "$boxId$faceId" の codeUnits (ASCII bytes)
  → 出力: 4桁HEX大文字（例: "6D77"）

generateQRCode(String boxId, String faceId)
  → "fujin://$boxId/$faceId/${generateChecksum(boxId, faceId)}"
```

### 7-2. 検証

```
parseQRCode(String qrCode)
  → "fujin://" プレフィックスチェック
  → "/" で分割して3セグメント確認
  → boxId: 8文字チェック
  → faceId: "F" 始まり + 2文字以上チェック
  → checksum: 4文字チェック
  → Map<String, String> { boxId, faceId, checksum, qrCode } を返却

validateQRCode(String qrCode)
  → parseQRCode() でパース
  → generateChecksum(boxId, faceId) で期待チェックサムを計算
  → QRに埋め込まれたチェックサムと一致するか検証
```

## 9. 共通Widget

### QRScanPage（shared/widgets/qr_scan_page.dart）

カメラを使ったQRコード読み取りの共通Widget。

| プロパティ | 型 | 用途 |
|-----------|-----|------|
| `onQRCodeDetected` | `Function(String)` | QR検出時のコールバック |
| `title` | `String?` | AppBarタイトル |
| `instruction` | `String?` | 画面下部の案内テキスト |
| `continuousMode` | `bool` | `false`: QR検出後にカメラ停止（確認用） / `true`: 検出後もスキャン継続（開封用） |

**通常モード（continuousMode: false）**:
- VerifyPage で使用
- QR検出 → カメラ停止 → コールバック

**連続モード（continuousMode: true）**:
- UnsealPage で使用
- QR検出 → コールバック → 500msウェイト → 次のスキャン受付
