## 2. データモデルの変更

### 2-1. BoxStatus（ステータス）

`sealed` の表示名を変更し、`stored` を新たに追加する。また `tampered` の表示名を「破損」から「異常検知」に変更する。

> **設計方針**: Firestoreへの保存値（内部値）は `tampered` のまま維持する。既存データとの互換性を保ちながら、アプリの表示名のみを実態に即した言葉に改める。`tampered` は「壊れた」ではなく「封印後に第三者が触れた痕跡がある可能性」を示す状態であるため、中立的な表現「異常検知」が適切と判断した。

```dart
// 変更前
enum BoxStatus {
  sealed('sealed', '未開封'),
  opened('opened', '開封済み'),
  tampered('tampered', '破損');
}

// 変更後
enum BoxStatus {
  sealed('sealed', '未保管'),      // ★ 表示名を「未開封」→「未保管」に変更
  stored('stored', '保管中'),      // ★ 新規追加
  opened('opened', '開封済み'),
  tampered('tampered', '異常検知'); // ★ 表示名を「破損」→「異常検知」に変更（内部値は維持）
}
```

### 2-2. BoxStorageInfo（保管情報・新規追加）

保管に関する情報を1つのクラスにまとめる。

```dart
/// 保管情報
class BoxStorageInfo {
  final String storageLocation; // 保管場所（テキスト）
  final DateTime storedAt;      // 保管日時
  final String storedByUserId;  // 保管を実施したユーザーの UID
  final List<BoxPhoto> photos;  // 保管時に撮影した写真（任意・最大5枚）

  const BoxStorageInfo({
    required this.storageLocation,
    required this.storedAt,
    required this.storedByUserId,
    required this.photos,
  });
}
```

### 2-3. Box（修正）

- `storageLocation`（`String`）を廃止し、`storageInfo`（`BoxStorageInfo?`）に置き換える
- `sealed` 状態では `storageInfo` が `null`、`stored` 以降は非 null になる

```dart
class Box {
  final String boxId;
  final String userId;
  final String? groupId;
  final DateTime createdAt;
  final DateTime updatedAt;
  final BoxStatus status;
  final BoxStorageInfo? storageInfo; // ★ storageLocation から変更。sealed 状態では null
  final int qrFaceCount;
  final DateTime? openedAt;
  final DateTime lastViewedAt;
  final Map<String, QRFace> faces;
  final List<BoxPhoto> photos;      // 封印時の写真（中身の証拠）
  final String memo;
  final List<BoxHistory> history;
}
```

## 3. Firestore ドキュメント構造の変更

### 3-1. boxes コレクション

```
boxes/
  {box-id}/
    metadata:
      userId: String
      groupId: String | null
      createdAt: Timestamp
      updatedAt: Timestamp
      status: "sealed" | "stored" | "opened" | "tampered"  # ★ stored 追加
      qrFaceCount: Number
      openedAt: Timestamp | null
      lastViewedAt: Timestamp
    storage:                          # ★ 新規追加。sealed 状態では存在しない
      storageLocation: String
      storedAt: Timestamp
      storedByUserId: String
      photos:                         # 保管時の写真（任意・最大5枚）
        - { url: String, storagePath: String, uploadedAt: Timestamp }
    faces: { ... }
    contents:
      photos: [ ... ]                 # 封印時の写真（中身の証拠）
      memo: String
    history:
      - { timestamp: Timestamp, action: String, details: String }
```

### 3-2. Firebase Storage 構造

```
boxes/
  {box-id}/
    photos/
      photo_0.jpg          # 封印時の写真（既存）
      ...
    storage_photos/        # ★ 新規追加：保管時の写真
      storage_photo_0.jpg
      storage_photo_1.jpg
      ...（最大5枚）
```

## 5. 画面設計

### 5-1. 保管画面（StoragePage）

| プロパティ | 内容 |
|-----------|------|
| ルートパス | `/storage/:boxId` |
| 遷移元 | 封印完了後の選択 / 箱詳細画面 / 確認画面（VerifyPage） |
| 遷移先 | 保管完了 → ホーム画面（`/`） |

**入力項目**

| 項目 | 必須 / 任意 | 制約 |
|------|-----------|------|
| 保管場所 | 必須 | 最大100文字 |
| 保管写真 | 任意 | 最大5枚・1枚あたり最大2MB（圧縮後） |

**UI構成**

```
[AppBar] 「保管する」

[保管場所入力]
  TextField（「例：倉庫2F・棚B」）

[保管写真]
  写真追加ボタン（カメラ / ギャラリー選択）
  サムネイル一覧（横スクロール）

[保管するボタン]
  保管場所が入力されていれば有効・それ以外はグレーアウト
```

### 5-2. 封印完了後の選択UI

封印完了後にダイアログを表示し、続けて保管するかどうかをユーザーが選択する。

```
┌──────────────────────────────────┐
│  封印が完了しました               │
│                                  │
│  続けて保管場所を記録しますか？    │
│                                  │
│  [あとで保管する]  [続けて保管する] │
└──────────────────────────────────┘
```

- 「続けて保管する」 → 保管画面（`/storage/:boxId`）へ遷移
- 「あとで保管する」 → ホーム画面（`/`）へ遷移（ステータスは `sealed` のまま）

## 7. 処理フロー詳細

### 7-1. 保管フロー（StoragePage）

```
[保管画面表示]
    │
    ├─ 保管場所入力: TextField → storageLocationController
    ├─ 写真追加: ImagePicker → File → selectedPhotos リスト（最大5枚）
    │
    └─ 「保管する」タップ
          ├─ バリデーション（保管場所が入力されているか）
          ├─ 保管写真アップロード: StorageService.uploadStoragePhoto() × N枚
          │     └─ boxes/{boxId}/storage_photos/ に格納
          ├─ BoxStorageInfo オブジェクト生成
          ├─ StoreBoxUseCase.execute()
          │     ├─ Box.status を stored に更新
          │     ├─ Box.storageInfo を設定
          │     ├─ 操作履歴に「stored」を追加
          │     └─ グループ共有されている場合は通知送信
          └─ 完了 → SnackBar + beamToNamed('/')
```

### 7-2. 封印フロー（変更後）

```
【封印完了後】
    │
    └─ 完了ダイアログ表示
          ├─ 「続けて保管する」→ beamToNamed('/storage/$boxId')
          └─ 「あとで保管する」→ beamToNamed('/')
```

### 7-3. 開封フロー（変更後）

```
[UnsealPage アクセス時]
    │
    ├─ FirestoreService.getBox(boxId)
    ├─ status チェック
    │     ├─ stored   → 開封フロー継続（既存の動作）
    │     ├─ sealed   → 「保管が完了していないため開封できません」を表示して戻る
    │     ├─ opened   → 「開封済みの箱です」を表示して戻る
    │     └─ tampered → 「異常が検知されています」を表示して戻る
```

## 11. 制約事項

| 項目 | 制限値 | 理由 |
|------|--------|------|
| 保管写真枚数 | 最大5枚 / 箱 | 封印時写真（最大10枚）と区別し、保管状況の記録として必要十分な枚数 |
| 保管場所文字数 | 最大100文字 | 封印時と同じ制約を維持 |
